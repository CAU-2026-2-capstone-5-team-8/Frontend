# 책길 — React Native + Expo

프로젝트의 유일한 프론트입니다. Expo SDK 57, React Native 0.86, Expo Router를 사용하며 iOS·Android·웹이 같은 화면과 API를 공유합니다.

2026-10-04부터 흰 배경·책 중심의 서점형 구성을 사용합니다. 넓은 화면은 상단 메뉴, 작은 화면은 본문을 덮지 않는 하단 메뉴를 제공합니다. [디자인 문서](../design.md)를 따르며 내부 근거·한계 설명은 사용자 화면에 표시하지 않습니다.

## 실행

Backend는 `ML_MODE=http`, 실제 ML 서버, 등록된 도서 projection과 진단 bank가 필요합니다. [서버·데이터 준비](../../Backend/docs/linear-algebra-live-handoff.md), [새 진단·추천 계약](../../Backend/docs/concept-learning-v1.md)을 참고하세요.

```sh
cd Frontend/native
npm ci
npm run web
```

웹은 `http://127.0.0.1:5183`에서 열립니다. 웹 요청은 동일 출처의 `/api`로 보내고 프록시가 Backend에 전달합니다. 개발 기본 주소는 `http://127.0.0.1:8087`이며, 운영에서는 `BACKEND_URL`을 반드시 지정합니다. 배포 이미지·HTTPS·서비스 연결은 [배포 문서](../docs/web-release.md)를 따릅니다. 모바일 API 설정은 웹 프록시 설정에 영향을 주지 않습니다.

모바일은 `.env.example`을 `.env.local`로 복사합니다. 사용자 ID는 회원가입·로그인 결과에서 결정합니다. `EXPO_PUBLIC_API_URL`에는 기기에서 접근 가능한 Backend 주소와 `/api`를 넣습니다. iOS 시뮬레이터는 `http://127.0.0.1:8087/api`, 기본 Android 에뮬레이터는 `http://10.0.2.2:8087/api`, 실제 휴대폰은 같은 네트워크의 PC 주소를 사용합니다.

```sh
npm start
# 필요할 때: npm run ios 또는 npm run android
```

## 화면과 데이터

- **내 계정**: 이메일 회원가입·로그인·로그아웃, 이름·소개·아바타·관심 분야 편집, 실제 저장된 진단 이력과 준비도 조회. 미평가 항목에는 점수를 만들지 않습니다.
- **책 찾기**: 등록된 분야의 실제 도서 목록, 페이지 이동, 책 상세와 선택적 검토 표지. 분야·권수는 현재 연결한 데이터베이스를 따릅니다.
- **개념 진단**: `/api/assessments/concepts`의 개념·능력별 선택 정책. 저장 성공 후 진행하며 이전 답변을 수정하고 진단을 이어할 수 있습니다. 정답은 서버에서 채점합니다.
- **나의 개념 지도**: 서버의 공통 개념 ID와 검토된 선수관계를 사용합니다. 뜻·성질 / 계산·적용 / 설명·추론을 바꾸어 보고 개념을 선택하면 평가 문항 수와 정답 수를 확인합니다.
- **책 상세**: 도서 정보·서재 담기·공개 후기와 읽기 전 살펴볼 개념을 표시합니다. 정답으로 확인한 내용, 복습할 내용, 아직 확인하지 않은 내용을 구분합니다.
- **맞춤 추천**: 키울 능력을 선택하고 선수개념 후보, 연습할 내용, 미평가 내용을 따로 봅니다. 기존 세 가지 총점과 자기평가를 새 추천의 실력 점수로 사용하지 않습니다.
- **복원**: 사용자·API 주소·분야별로 진단/추천 ID를 보관하고 서버 결과를 재조회합니다. 추천 재조회는 새 계산을 만들지 않으며, 전송 실패 재시도용 키도 저장합니다.

## 현재 검증과 과거 평가 범위

2026-10-04 검증에는 현재 수집 파일의 실제 운영체제 도서 25권을 사용했고 7권에 개념이 연결됐습니다. 진단은 사람 검토 객관식 1문항과 명시적으로 구분한 로컬 자기평가 8문항입니다. 이는 완성된 운영용 문제 은행이 아닙니다. [현재 검증 기록](../docs/release-verification-2026-10-04.md)을 우선합니다. 아래 수치는 이전 환경의 역사적 기록이며 현재 서비스의 카탈로그 규모를 뜻하지 않습니다.

선형대수 진단 bank는 자기평가 8개와 승인된 객관식 1개입니다. 현재 객관식은 행렬의 계산·적용만 확인하므로 나머지 개념·능력 칸은 미평가입니다. 자기평가는 별도 기록이며, 정답 1개를 숙련도 확률로 표현하지 않습니다. 기존 세 영역의 저장 필드는 호환성을 위해 남아 있습니다.

471권 목록 중 선형대수 83권에 분석 projection이 있고 공통 개념이 연결된 것은 11권입니다. 나머지 72권은 새 추천에서 판단을 보류합니다. 다른 분야는 목록 조회를 제공하며 준비된 bank가 없는 분야는 진단 시작을 막습니다. 수집 목록은 아직 도서 유형별 선별 전입니다.

목차는 내용 연결에 사용하며 책의 설명 깊이·본문 독해 난이도는 미확인으로 둡니다. 새 추천은 관찰 결과를 사용하는 설명 가능한 첫 기준선이며 추천 품질을 검증한 모델은 아닙니다. 회원가입·로그인 후 자신의 진단과 추천을 사용합니다. 이 단락의 471권/83권 수치는 이전 카탈로그 검증 DB 기준이며, 현재 계정 연결 검증용 별도 DB에는 실도서 3권만 등록했습니다.

## 문제의 Markdown·LaTeX 표시

## 계정 연결 검증 (2026-10-03)

Backend 계정 main과 로컬 개념 진단·추천을 `feat/account-concept-integration`에서 통합했습니다.
[서버 통합 기록](../../Backend/docs/account-concept-integration.md)을 참고하세요.

- 비회원은 도서·공통 개념을 탐색하고, 개인 진단·추천은 로그인 후 이용합니다.
- 모바일 토큰은 Expo SecureStore, 웹은 현재 탭의 sessionStorage에 저장합니다. 웹 새로고침은 복원하고 탭을 닫으면 로그인 보관이 끝납니다.
- 진단·추천·재시도 키는 API 주소·계정·분야별로 분리합니다. 계정 변경 시 화면 상태를 초기화하고 이전 계정의 늦은 응답은 버립니다.
- 인증 만료/401은 로그인을 해제하고, 다른 계정 자료 접근의 403은 로그인 상태를 유지하며 오류로 표시합니다.
- 로컬 웹 프록시는 Authorization을 Backend에 전달합니다. 사용자 ID만 설정하는 이전 방식은 제거했습니다.

`npm run check`는 타입·린트와 인증 7개/콘텐츠 표시 5개 검사를 포함합니다. 웹 및 iOS·Android 번들 생성도 통과했습니다.
두 계정의 회원가입·프로필 저장·새로고침·진단 이어하기/완료·추천 저장/복원·이력·로그아웃·폐기된 세션 복원을
실제 PostgreSQL/Backend/ML과 브라우저에서 확인했습니다. 타 계정 조회/사용자 ID 위조는 403이며 320/390/768/1280px 가로 넘침과 실행 오류는 없었습니다.
결과는 ignored `.local-checks/account-check.json`, 화면은 `account-*.png`입니다. 이 검증은 합성 계정과 실도서 3권을 이용했으며 추천 정확도나 네이티브 실기기 동작을 입증하지 않습니다.


## 내 서재와 공개 한줄평 (2026-10-03)

`/shelf`에서 책별 읽기 상태(읽고 싶어요·읽는 중·완독), 나만 보는 메모와 공개 한줄평을 관리합니다.
책 상세의 ‘내 서재에 담기’로 시작하며 중복 담기는 기존 상태·메모를 보존합니다. 목록은 상태별 필터와
페이지 이동을 지원하고, 화면에 돌아오면 서버의 최신 데이터를 다시 조회합니다.

- 메모(최대 1,000자)는 계정 전용입니다. 공개 한줄평(최대 300자)과 체감 난이도는 별도 저장합니다.
- 책 상세의 공개 후기 목록은 비회원도 볼 수 있으며 개인 메모·실명은 포함하지 않습니다.
- 서재에서 제외하면 개인 메모도 삭제되며 공개 후기는 유지합니다. 후기 삭제는 별도 동작입니다.
- 저장 성공 응답을 받은 뒤에만 성공으로 표시합니다. 저장 실패 시 입력을 유지하고 다시 저장할 수 있습니다.
- 새 계정으로 전환하면 화면 상태를 초기화합니다. 이전 계정 요청의 늦은 응답은 적용하지 않습니다.
- 체감 난이도는 독자의 경험 기록이며 ML 난이도나 추천 점수에 합치지 않습니다. 사진 촬영/OCR은 후속 범위입니다.

검증: 타입·린트, 기존 인증 7개/콘텐츠 5개와 새 프록시 HTTP 2개 검사, 웹·iOS·Android 번들 생성 통과.
실제 로컬 PostgreSQL/Backend와 두 테스트 계정에서 담기·중복 담기·상태/메모 저장·공개 후기·새로고침·필터·
계정 격리(조회/삭제 403)·삭제 취소/확인·후기 유지/별도 삭제를 확인했습니다. 응답 실패를 주입했을 때도
초안이 보존되고 DB는 바뀌지 않았습니다. 320/390/768/1280px에서 가로 넘침·실행 오류가 없었습니다.
결과는 ignored `.local-checks/shelf-check.json`, 화면은 `shelf-editor-*.png`입니다. 네이티브는 번들 생성까지 확인했고 실기기는 미검증입니다.

문항 검토 화면은 로컬 Backend의 `assessment.preview-dir`을 새
`Question-Generation/data/generated/concept-assessment-reviewed-draft-v3`로 지정하면 수정된 후보를 표시합니다.
기저 의미 문항의 필요충분조건 표현만 수정됐으며 사람 승인 전 후보라는 경계는 같습니다.
